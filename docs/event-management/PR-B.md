# Johnny waiting lists — draft, no rollout authorised

Stacked on PR A, not PR80/81. Migration 0041 follows 0040; no policy seed, customer data backfill, production connection or cron configuration change.

Verified email starts a DB-sequenced FIFO entry per product (the product defines dates/session entitlement); group quantity is indivisible. An earlier waiting group blocks every later group in that product even when a smaller group fits. Active email/product uniqueness prevents duplicate requests. Status and leave use a hashed, scoped HttpOnly Secure cookie after one-use email verification. Rejoin after expiry creates a new sequence position. Public sold-out admission products link to the waiting list only when its flag is enabled.

An atomic offer creates an existing special_event_holds reservation, hold-day entitlements, one durable notification and audit. All holds are protected by shared product/day/evening/competition DB capacity checks. Default offer is 1440 minutes (owner configurable for future offers). Owner bypass requires a reason and immutable audit. No reminders. Expiry/leave releases once. Accepting changes that same hold to a 15-minute checkout window; duplicates do not extend it. Current release/pricing and existing checkout eligibility/password/junior/guardian conditions are rechecked; closed tiers never reopen automatically. Hosted SumUp checkout reuses the original hold (no double reservation), and a single-use durable checkout claim blocks simultaneous checkout creation. Original authoritative payment path remains responsible for fulfilment. A capture after waiting-list checkout expiry is manual review, not automatic ticket allocation.

Offers reserve admission only. Optional competition add-ons must be bought separately through the existing qualifying-admission workflow; the waiting-list checkout explicitly rejects adding unreserved competition places. This is a visible development limitation; no entitlement is silently removed. ADD_ON waiting queues are not implemented yet: current eligible queues are admission products only. A lost checkout response can resume via an authorised GET of the exact stored checkout; an unlinked/uncertain provider checkout requires owner review, never a second creation.

The new outbox uses the shared sender/claim processor with a whitelisted table name and durable provider keys. Unknown send outcome remains manual review. Successful cancellation POST schedules a bounded queue pass only after commit. Existing scheduled handler adds independent queue/notification work without changing cron times; jobs use Promise.allSettled so failure cannot prevent other jobs. Existing outbox/confirmations are retained. Hourly expiry processing may leave a stale display until processing, but SQL expiry prevents acceptance and expired holds no longer consume capacity at the exact deadline.

Flags default OFF: EVENT_WAITLIST_ENABLED, EVENT_WAITLIST_OFFERS_ENABLED; notifications additionally require EVENT_MANAGEMENT_NOTIFICATIONS_ENABLED. No live offers or messages have been generated.

Tests: synthetic email verification/replay, group blocking, owner override/audit, exact shared capacity, concurrent offers/acceptance, no reservation extension, one notification, expiry/release and closed/pricing restrictions. Full main regression suite also runs. Further authenticated browser testing and combined PR80/81 end-to-end validation remain rollout gates.

Rollout: PR80/81 integration and PR A first; authorised synthetic staging applies 0040 then 0041, flags OFF, existing checkout regression, then enable synthetic queue and offers separately. No staging/production deployment is authorised by this PR. Review rate limits, message copy and owner override UX before independent production approval.

Rollback: disable joining/offers and stop new notifications; retain expiry processing, checkout claims and effective allocation kernel. Preserve active offers until honouring or explicitly owner-reviewed resolution; do not delete holds, expire live offers without approval, restore cancelled admissions or remove audit/payment records. Keep additive tables. Restore the compatible prior worker, never a version that ignores released-admission decisions.
